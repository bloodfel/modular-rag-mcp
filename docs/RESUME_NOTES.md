# 简历素材与面试话术

> 数字全部来自真实跑批，出处见 [docs/RESULTS.md](RESULTS.md)。

## 1. 简历 essentials（①②为核心，③按岗位取舍）

**① 质量闭环：双层评测体系 + CI 质量门禁，分数回写每条请求**

> 为自研 RAG 系统建立"离线金标 + 在线 LLM-as-Judge"双层评测体系：人工核对的检索金标
> （231-chunk 语料，hit@10 = 1.0，MRR / nDCG@10 基线）考核检索，Ragas 四指标在线评审
> （faithfulness 0.96 / context_recall 0.92，60 例标注集）考核生成，评测分数自动回写
> Langfuse trace——每条真实请求自带质量分，坏 case 一眼可见。同一金标接入 CI 质量门禁：
> 每次代码变更自动重跑检索评测，指标低于阈值（hit_rate / MRR / nDCG）自动阻断合并。

**② 成本与决策：全链路可观测，三项数据驱动选型**

> 搭建 OpenTelemetry → Langfuse 全链路可观测（延迟 / token / 成本按阶段归因，单文档
> 入库成本 $0.000985 全程可见），并以实测数据完成三项组件决策：重排器选 Jev
> （+8.3 nDCG@10，相对 +12.8%，$0.17/千次查询）、LLM 由 GLM 切换 DeepSeek
> （单次调用 36.4s → 1.2s，≈30×）、召回阈值 4.0 → 1.0（消除 24% 空结果）。

**③ 可靠性：三级优雅降级，失败路径全部可观测**（投偏平台 / 基建岗时加）

> 设计并落地三级降级路径（重排失败 → 融合排序、嵌入失败 → BM25-only、LLM 增强 →
> 规则回退），每次降级在 trace 打标、回退率可统计；将"静默降级"（如图片提取失败仅留
> 日志）改为 trace 显式标记 + 看板警告，消除无告警的质量损失。

## 2. 这两条怎么讲（面试 30 秒版）

叙述模板万能句：**发现问题 → 建度量 → 数据 → 决策 → 效果**。

- 条①：RAG 上线后答不出"回答质量到底好不好" → 离线金标考检索、Ragas 在线评审考生成 →
  四指标分数直接挂在每条 trace 上 → 平均分、不及格的请求、最差 case 全部可见。
- 条②：入库一次 44 秒、不知道钱花在哪 → 全链路打点上报 Langfuse → 数据显示文本精洗占
  90% 耗时、GLM 单次 36 秒 → 切 DeepSeek 提速 30×、成本千分之几美元 → 阈值实验再消掉
  24% 空结果。**别上来就讲工具，讲这个链条。**

## 4. 被追问时的诚实边界

- 60 条标注集是 LLM 起草、带溯源 chunk，**未全量人工复核**——被问就答"抽样核对，全量复核是下一步"。
- Ragas 评委与生成器同为 DeepSeek，存在同源偏好；换评委是配置级改动。
- CI 门禁已建并本地双向验证；**GitHub 云端首跑待推送触发**（阈值：hit_rate ≥ 1.0 / mrr ≥ 0.45 / ndcg ≥ 0.48）。
- fiqa 5.7 万语料大基准延期；安全鉴权明确范围外。
